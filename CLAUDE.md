# new-horizons — operating rules

Offline analytics agent for one aquaponics farm ("the Farm"): four grow units, five
synthetic source systems, one Streamlit app, one LangGraph agent. Also the home of
the shared harness package (`new_horizons.shared`) that sojourner imports.
Built for one MacBook Pro, 16 GB. MIT, synthetic, seeded (`seed: 2019`).

## Run

- `source scripts/ollama-env.sh && ollama serve` (separate terminal) → `make db-up` →
  `make demo1`. First time only: `make models`, `uv sync`, `make mock` (five databases +
  analytics + sample scans), `make kb` (knowledge base, ~5 s).
- Layout: `src/new_horizons/{shared,app,host}`. `shared/` never imports `app/` or
  `host/`, and views never import each other — `make lint` (import-linter) enforces both.
  The app registers its farm tools and metrics layer with the harness
  (`app/analytics/agent_tools.py` → `toolbox.register`, `graph.register_metrics`).
- Paths hang off `new_horizons.paths.ROOT` (the checkout; `HORIZONS_HOME` when the
  package is installed elsewhere). Data lives in `data/` (gitignored except `_seed/`).
- Governance: decisions and the kill switch are AUDIT EVENTS (`shared/audit/audit.py`:
  record_decision / set_agent_state / decisions / events), never UI state or a side
  table — the drawer renders the chain itself. Pausing the agent stops document intake
  and chat answers. `U.approval_bar` / `U.audit_link` / `U.audit_dialog` are the only
  ways to raise a decision (Awaiting · Farm Manager → Approve / Escalate to owner /
  Reject); the Admin center renders `agents/analytics/GOVERNANCE.md` with live facts next
  to the inline audit trail; pause/resume and the model switch live in Settings.
- One audit chain: sojourner writes its approved deploys into the same
  `audit_log` (`event_type` `deploy`, payload `source: sojourner`); the Changes page reads them.
- Knowledge base stays GENERIC for any farm. Local rules go in `ingest/kb_market/<name>/`
  with their own citations.yaml, switched on by `profile.yaml -> market.kb_overlays`. A
  doc whose front matter has a `status:` line is a skeleton: build skips it and its keys.
- Business truth is pinned by `tests/test_validation.py` against `ingest/validation/`,
  which the generator writes — never typed by hand. The bilingual scorecard:
  `uv run python scripts/question-bank.py --set docs/question-set.yaml [--model llama3.1:8b]`
  (regenerate the .md with `--render-md`).
- Chat correctness is enforced in code, not the prompt (`docs/brief-agent-hardening.md`).
  Known questions: `agents/analytics/intents.yaml` → `analytics/metrics.py` resolvers,
  answered with the resolver's template (model phrasing is opt-in,
  `METRICS_PHRASING=model`). Everything else goes to the free agent: follow-up rewrite,
  figure gate, figure verification (`shared/text/lang.py`), language enforcement
  (`shared/harness/graph.py`). The schema in the prompt is generated
  (`shared/db/introspect.py`). Never put schema, status values, dates or example figures
  into `SYSTEM.md`. Fix a missed question with a paraphrase, a `not:` example or a
  resolver, then re-run the set.
- UI = Agentization Core design system: colours only in `app/design/tokens.json`, three
  themes (black default, white, gray) → `design/ac.css`, `app/.streamlit/config.toml`
  (= the default theme; hand-maintained; `scripts/brand-sync.py` mirrors it for the host),
  Streamlit's runtime theme (`U.apply_theme`, picked in Settings, saved in
  `data/ui_settings.json`), the Plotly `ac` template. Sidebar = farm logo
  (`assets/brand/horizons-mark.svg`, gray-ink twin on White) → 3×3 grid of icon
  `st.page_link`s (`U.NAV` seven analysis pages + `U.NAV_EXTRA` Admin center, Settings),
  name rising in a glass tag on hover → footer band (AC mark · sojourner mark, same ink area,
  gray ink on White). Marks are generated by `scripts/brand-marks.py` — never traced or
  hand-drawn. Page files live in `views/` — never `pages/` (Streamlit's MPA-v1 mode would
  run a deep-linked page without app.py: no CSS, no sidebar).
- Smoothness: navigate with `st.page_link`, never a button + `st.switch_page`; a click
  that changes one panel is a callback inside an `st.fragment`, not `st.rerun()`;
  Streamlit's stale-element fade is off in `ac.css`. No `cursor` rules. The only JS is
  `design/ac-lens.js` (the nav name tag). Hover, tooltips and state are CSS.
- Language: English or Arabic for the whole app (Settings; right to left via `--ac-dir`,
  logical CSS properties). Every UI string is written `tr("English", "العربية")` where it
  is used — never an Arabic twin beside English. Data keeps its own language.
  `GOVERNANCE.ar.md` is the handoff doc's twin; tests keep them in step.
- Every screen with operational data carries the "Synthetic data" chip.
- Inference lane: `make llm-target MODE=local|rented|claude|hybrid [URL=… MODEL=…]`
  rewrites `.env` and, when the sibling checkout exists, sojourner's tier env files.
  `shared/llm/provider.py` returns TWO endpoints: chat (switchable) and the Ollama host
  (always local). Embeddings (bge-m3) and the vision model (qwen3-vl) never follow chat.
- Tests: `make test` (needs `make db-up`; the farm tests need `make mock kb`). CI runs
  `pytest -m "not model"`, `make lint` and `make client-free`.

## Hard rules

- **Never install vLLM locally** — no Metal backend. Every LLM call stays on the
  OpenAI-compatible endpoint; never call a provider SDK directly.
- **Never imply local inference when a remote lane is active.**
- **Memory budget**: one 8B chat model resident; `qwen3-vl:4b` on demand with
  `keep_alive: 0`; `num_ctx` 8192 (`OLLAMA_CONTEXT_LENGTH`); KV cache q8_0.
- **Sequencing**: never run `make demo1` and sojourner' tier stack together.
  Postgres alone is fine — both use the same container and volume.
- **Tool calling**: JSON tool protocol only (`shared/harness/protocol.py`) — never
  `bind_tools`; the graph runs identically on qwen3:8b, llama3.1:8b and deepseek-r1:8b.
- **Synthetic and client-free**: no real company, farm or person anywhere; the data and
  the KB say "the Farm". `make client-free` must stay green.
- Numeric answers cite `(source, section)` from the KB or name the tool/query used.
  Discrepancy detection is deterministic code (`analytics/recon.py`); the LLM only
  explains and recommends from retrieved KB terms (`ingest/kb_synthetic/citations.yaml`).
